# 工单 / 工单分析 · 可视化原型

Room Node Console 增加「工单（工单 / 工单分析）」模块的可交互静态原型，用于评审
**是否要做工单系统、工单长什么样、状态如何流转、历史数据怎么分析**。

完全自包含：`index.html + styles.css + app.js`，不依赖任何 CDN、外部字体或外链图片，
可直接用 `file://` 打开（也可 `python3 -m http.server` 起静态服务）。纯演示，没有后端请求。

## 打开方式

直接双击 `prototype/tickets/index.html`，或：

```bash
cd prototype/tickets && python3 -m http.server 8765
# 访问 http://127.0.0.1:8765/index.html
```

## Hash 路由

| hash | 视图 | 说明 |
| --- | --- | --- |
| `index.html#list` | 工单列表（默认） | KPI 条、状态页签、筛选、表格、分页、新建工单入口 |
| `index.html#detail/t28` | 工单详情 | 用 mock 工单 id（`t01`–`t32`）；也可用编号如 `#detail/T-20261101-0001` |
| `index.html#insights` | 工单分析 | 近 7 / 30 / 90 天统计与图表 |
| 新建工单 | 列表页弹窗 | 顶部「新建工单」或空状态按钮打开，不单独占 hash |

示例：`#detail/t28` 是 room-101 GPU 温度告警（处理中，含系统 / 人工时间线与评论），
适合演示状态操作；`#detail/t18` 是一张**已超 SLA 的处理中**工单，适合演示超时场景。

## 交互清单

**列表页**

- KPI 条：待处理 / 处理中 / 已解决 / 超时，均来自同一份 mock 数据实时计算。
- 状态页签：全部 / 待处理 / 处理中 / 已解决 / 已关闭 / 已取消，数字随筛选条件变化。
- 筛选：优先级、分类、处理人（含「未分配」）、关键词搜索（编号 / 标题 / 房间 / 设备 / 序列号 / 信号）、
  时间范围（全部 / 近 7 天 / 近 30 天）；「重置」一键清空。
- 表格按更新时间倒序；点击任意行进入详情；分页 10 条/页；无结果时显示空状态。
- 「新建工单」打开弹窗：标题必填，可填分类、优先级、关联房间 / 设备 / 机器与描述；
  提交后生成 `T-YYYYMMDD-####` 编号、插入列表并直接打开详情。

**详情页**

- 返回链接、编号 + 标题 + 状态 / 优先级 / 分类 / 来源徽标、上报人 / 创建时间 / 处理人。
- 操作按钮随状态变化，每次操作都会：更新状态、追加一条时间线、弹出 toast；
  新的时间戳仍按 mock 的「今天 18:35」之前推导，分析页口径保持一致。

| 当前状态 | 可用操作 | 结果 |
| --- | --- | --- |
| 待处理 | 认领 / 开始处理 / 取消 | 认领只指派处理人；开始处理→处理中；取消→已取消 |
| 处理中 | 标记解决 / 取消 | 标记解决→已解决并记录解决时间；取消→已取消 |
| 已解决 | 关闭 / 重开 | 关闭→已关闭；重开→待处理并清空解决时间 |
| 已关闭 / 已取消 | 重开 | 回到待处理 |

- 问题描述 + 触发信号（自动工单展示规则与快照 / 事件引用，人工工单展示「人工上报」）。
- 关联上下文：房间、区域、机器节点、序列号、健康与在线状态，以及「查看机器详情」入口
  （原型中只弹提示，正式实现跳转 `/machines/{serial}`）。
- 工单信息（编号 / 状态 / 优先级 / 分类 / 来源 / 上报人 / 处理人 / 创建 / 更新 / 解决时间 / SLA 时限）、
  SLA 卡片（时限、消耗进度、按时 / 超时 / 剩余时间）。
- 处理时间线：系统条目（自动创建、自动指派、SLA 超时升级）带「系统」标记，
  人工状态变更与评论区分展示；支持提交评论（⌘ / Ctrl + Enter 快捷提交），
  已关闭 / 已取消工单会锁定评论框。
- 所有改动只写浏览器内存，刷新页面即恢复初始 mock。

**分析页**

- 时间范围：近 7 天 / 近 30 天 / 近 90 天，切换后所有数字与图表重算。
- KPI：新增工单、已解决、未关闭、平均处理时长、超时工单，并展示与上一周期对比。
- CSS-only 分组柱状图：按日对比「新增 vs 关闭」，无任何图表库；悬停柱体可看当日明细。
- 分类分布横向条形图、房间 TOP5、设备 TOP5、处理人负载（按状态堆叠）。
- 底部自动生成一条「重复故障 / 高频告警」洞察：从同一数据集里找同房间同类工单聚集，
  例如近 30 天 `room-102` 的机器健康类工单重复触发。
- 口径：新增 = 创建时间落在区间；已解决 = 解决时间落在区间；未关闭 = 区间内创建且
  未关闭 / 未取消；超时 = SLA 到期时仍未解决（已解决但晚于时限也算超时，已取消不计）。

## Mock 数据

- 32 张工单，创建时间在 2026-10-03 ~ 2026-11-01（近 30 天），「当前时间」固定为
  2026-11-01 18:35（UTC+8），保证不同时区截图 / 演示一致。
- 8 个房间（room-101 ~ room-108）、8 类设备、机器序列号与 `room-XXX-node` 主机名。
- 3 个处理人（张伟 / 李娜 / 王强）+ 未分配；当前登录用户为张伟（侧边栏 / 顶栏头像）。
- 覆盖全部状态（待处理 8 / 处理中 6 / 已解决 6 / 已关闭 9 / 已取消 3）、
  4 个优先级、6 个分类（机器健康 / 设备离线 / 推送失败 / 分发失败 / 安全 / 其他）、
  自动创建（24 张，含机器健康、离线、排课事件推送、镜像分发信号）与人工上报（8 张）。
- 编号按创建日流水生成 `T-YYYYMMDD-####`，时间线、SLA、评论与列表 / 分析页全部同源。

## 设计说明

- **复用既有控制台外壳，不新增 layout**：直接从 `prototype/schedule-board/` 复刻侧边栏
  （248px，品牌 Room Node / console、房间节点管理卡、导航分组、底部用户）、顶栏
  （面包屑 / 全局搜索 / 通知 / 头像）与底部状态栏；设计 token 取自
  `frontend/src/assets/main.css`（canvas / surface / line / ink / muted / accent / accent-soft）。
- **导航最小增量**：只在侧边栏新增一个「运维」分组（NEW 标记），内含「工单」「工单分析」两项；
  现有导航项保留占位，点击提示该页面已存在于既有控制台。正式实现复用 `DefaultLayout`，
  在 `AppSidebar.vue` 增加一个 nav group 与两条路由即可，无需独立 layout。
- **不引入新依赖**：无 Vue、无图表库、无图标字体。图标为内联 SVG sprite，图表为纯 CSS 柱状 /
  条形 / 堆叠条；离线 `file://` 可用。正式实现同样约束：图表用 CSS / HTML 或既有组件，
  不新增 ECharts 等依赖。
- **静态 mock、无接口**：列表 / 详情 / 分析共享同一数组，所有派生数字现算；状态流转、新建、
  评论只改内存。正式实现对接 `/api/v1` 后，页面结构、筛选与图表口径可直接沿用。
- **桌面优先**：目标 1440×900，最小宽度 1280；窄屏下隐藏筛选标签与按钮文案兜底。
- **产物定位**：这是用于产品决策的**分析型原型**，不是生产代码；不修改 `frontend/`、
  `crates/`、`migrations/`、根 `README.md` 或 `package.json`，也不请求后端。
