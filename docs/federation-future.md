## 1. 一句话定位

**把多个独立控制节点（校区 / 楼宇 / 机房）汇聚成一个只读或可控的教育云总控平面。**

不是再做一个“大屏”，而是解决：

- 多校区各自一套控制面，缺少统一资产/在线率/告警视图；
- 跨校区的教室、镜像、课表、工单无法统一治理；
- 中心需要看到全局，但不能把各校区的实时控制流量全部收口到中心。

## 2. 目标架构（云 — 边 — 端）

```text
                         ┌──────────────────────────────┐
                         │        中心总控平面           │
                         │  总览 / 资产 / 告警 / 审计     │
                         │  跨校区策略（只读优先）        │
                         └──────────────┬───────────────┘
                                        │ mTLS + 联邦 token
                 ┌──────────────────────┼──────────────────────┐
                 │                      │                      │
        ┌────────▼────────┐    ┌────────▼────────┐    ┌────────▼────────┐
        │ 区域控制节点 A   │    │ 区域控制节点 B   │    │ 区域控制节点 C   │
        │ 房间/设备/课表   │    │ 房间/设备/课表   │    │ 房间/设备/课表   │
        │ 本地自治         │    │ 本地自治         │    │ 本地自治         │
        └────────┬────────┘    └────────┬────────┘    └────────┬────────┘
                 │ mTLS                  │ mTLS                  │ mTLS
        ┌────────▼────────┐    ┌────────▼────────┐    ┌────────▼────────┐
        │ 教室 agent 集群  │    │ 教室 agent 集群  │    │ 教室 agent 集群  │
        │ 遥测/VM/镜像/显示│    │ 遥测/VM/镜像/显示│    │ 遥测/VM/镜像/显示│
        └─────────────────┘    └─────────────────┘    └─────────────────┘
```

设计原则：

1. **本地自治优先**：断网时校区仍能开课、管设备；中心只做汇聚，不做单点强依赖。
2. **只读先于写入**：先聚合资产/在线/告警，跨节点写操作最后做。
3. **零信任**：节点间 mTLS + 短期联邦凭证，不靠“内网所以安全”。
4. **失败隔离**：某个校区离线只影响该节点卡片，不拖垮全局。

## 3. 能力阶段

| 阶段 | 能力 | 价值 | 状态 |
| --- | --- | --- | --- |
| F1 只读聚合 | 节点注册、手动刷新、全局 KPI（房间/机器/在线/工单/镜像） | 中心看得见 | 已实现后下线，代码归档 |
| F2 自动同步 | 定时心跳、拓扑自动发现、节点健康、告警聚合 | 不用人工刷新 | 规划 |
| F3 统一治理 | 统一身份/RBAC、跨校区资产目录、镜像与策略分发 | 中心可管 | 规划 |
| F4 跨域调度 | 跨校区课表/实验环境/镜像 P2P、容量调度 | 云边协同 | 远期 |

## 4. 技术难点（PPT 可展开）

- **分布式身份**：节点证书、联邦 token、租户隔离、密钥轮换。
- **聚合一致性**：各节点时钟/网络不稳定，KPI 只能最终一致；需要缓存 + 快照时间。
- **只读与写操作分层**：跨节点关机/建 VM 涉及审批、审计、幂等和失败补偿。
- **故障隔离**：中心不可用不影响本地教学；校区不可用不阻塞其他校区。
- **数据边界**：哪些数据可以出校（资产/计数） vs 必须留在本地（学生/画面）。
- **可观测性**：联邦链路自身的延迟、错误率、证书到期、节点漂移。

## 5. 典型场景

1. **教育局/集团校**：中心看各校区在线率、告警、镜像覆盖率。
2. **多机房高校**：不同楼宇各自控制节点，中心统一资产与工单。
3. **考试保障**：中心汇总各校区设备健康，考前发现离线/磁盘满。
4. **跨校区实验环境**：镜像/课程模板统一分发，环境在本地执行。

## 6. 验收指标（未来真正做时）

- 两个控制节点注册后，5 分钟内自动出现在总览（无需手动刷新）。
- 单节点离线不影响其他节点数据展示；缓存标注“最后成功时间”。
- 聚合 KPI 与各节点本地统计误差 = 0（同一时间窗口）。
- 跨节点操作（如果做）具备审批、幂等、审计、失败回滚。
- 节点 token 不出现在日志/前端/API 响应中。

## 7. PPT 可用表述

适合放在“未来规划 / 演进路线”页：

> 从“单校区控制面”走向“区域教育云”：
> 本地自治，云端汇聚；先只读总览，再统一治理，最后跨域调度。

> 每个校区保留完整控制能力，中心通过零信任联邦获取全局视图，
> 网络中断时教学不中断。

**不要这样写**：

- “已实现多校区统一控制”
- “支持跨校区分发/关机”
- “已有中心总控平台”

当前真实状态是：**单控制节点可用；联邦为未来规划，入口和 API 已下线。**
